Executive summary

  • Mythos = frontier AI model by Anthropic (released ~April 2026) with unusually strong ability to detect software vulnerabilities, reason about cyber security and analyse whole software systems — at machine speed and scale.
  • Core mechanism: it finds zero-day vulnerabilities (flaws unknown to the maker, so zero days to fix). Finding is fast; patching is slow → defender overload.
  • Double-edged sword: defence (find & fix first) vs offence (exploit first, incl. non-state actors with a low entry barrier).
  • More than cyber security: hits critical infrastructure, BFSI, DPI, national security, citizen safety and sovereignty (India depends on foreign AI for cyber defence).
  • Question to ask is not "AI good or bad" but who gets access, under what safeguards, with what accountability.
  • Cyber security is a static topic (~9 UPSC questions 2013–25); Mythos is the current layer to insert into it.

1. Introduction — what is Mythos 0:20 – 0:35

Mythos: a frontier AI model developed by Anthropic, with unusually strong capabilities in (a) detecting software vulnerabilities, (b) cyber-security reasoning, (c) overall software analysis. Learn the exact definition; paraphrase in your own words in the exam.
  • What differentiates it from other LLMs (ChatGPT, Grok, Claude, DeepSeek): the concern is its zero-day detection at speed and scale and its autonomy — not that it is "another chatbot".
  • The competition among AI firms has shifted from "whose LLM is best" to whose frontier model can exploit zero-day vulnerabilities — the AI cyber arms race (a term used in a Hindu article ~3 weeks before the class). China-based Qihoo 360 (Q360) is also developing similar capability.
  • Anthropic reportedly withheld general release, forming a cohort of ~40 companies under Project Glasswing 0:50 — [Prelims-relevant].
  • Tie to history: Dario Amodei, Anthropic CEO, previously a research head at OpenAI; split from Sam Altman's OpenAI. Anthropic valuation quoted ~US$380–400 bn vs India's GDP ~US$3.2–3.3 tn (comparison style the lecturer wants for numbers).
Mythos was not built for cyber security — it is a general model whose capability turned out cyber-relevant. Useful nuance for "dual-use" answers.

2. Zero-day, patch, frontier AI — keywords with diagram 0:30 – 0:50

Frontier AI model: the latest and most advanced class of AI systems, capable of (1) complex reasoning, (2) autonomous task execution, (3) code generation and, most importantly, (4) cyber-security work. Examples named: Mythos (Anthropic), also ChatGPT, Claude, Grok.
Zero-day vulnerability: an undisclosed flaw in software or hardware that threat actors can exploit and which the developer does not know exists. Called "zero-day" because the developer has zero days to fix once it is found — they don't yet know the solution.
Patch: the technical term for a fix/update that resolves a bug or vulnerability in software (e.g. phone/firmware updates).

Diagram — software → bug → patch

Developer builds software (Windows / Linux / banking app) uses maths + coding principles
  ↓ inherent bugs exist, unknown to developer (old ones can stay hidden for decades)
Frontier AI (Mythos) scans at speed & scale → finds the bug = "zero-day"
  ↓ developer has 0 days / no known solution
Two paths: (A) defender gets it first → patch → prepare defence against the flaw
             (B) threat actor gets it first → exploit

Who is hit: (1) software developers (e.g. Microsoft for Windows) — their flaws exposed; (2) cyber-security threat detectors (makers of antivirus/threat-detection software) — even they do not know how to resolve it. Both lose.

Facts to insert

  • Example lecturer gives: a software built by a big US company had a bug undetected for ~27 years — Mythos-type autonomous coding (under human oversight) could reveal such flaws in a short span.
  • Fact (Example box): Mythos found over 10,000 major software vulnerabilities within a month 2:05 (lecturer's figure — verify).
  • Two keywords from the Hindu article by a senior IAS officer (Shri Vatsa Krishna): "zero-day vulnerabilities", and speed & scale.

  • Offence: by non-state actors.
  • Double-edged sword because it is a tool of defence (defenders secure systems) and of offence (potential attackers discover and exploit vulnerabilities).

6. Cyber-security implications 2:00 – 2:20

  1. High vulnerability discovery at machine speed — diagram: "Mythos and zero-day vulnerabilities"; Example: over 10,000 major software vulnerabilities in a month.
  2. Defender overload — AI finds vulnerabilities faster than institutions can verify, prioritise and patch. The response mechanism itself fails. Keyword: defender overload (from an Indian Express/Hindu Parley article by Sharada Tickoo, as cited; most newspaper pieces on this are not by subject experts).
  3. Supply-chain security — modern systems run on shared libraries, open-source components, cloud services, third-party vendors. Software is interconnected; if one leg fails the chain fails (like an assembled desktop: one broken component stops the class). Parallel with the Western China-plus-one, de-risking, geo-economics logic.
    • Open-source example: Zoho (government software/website/database outsourced to Zoho Corporation — lecturer's example, also sceptical of previous supplier TCS).
    • Cloud example: MeghRaj (government cloud; like Google Drive/iCloud for Government of India data).
  4. Shift in nature of attacks — more scalable (higher frequency), more automated, more accessible (low entry barrier). A significant threat because many financial institutions run on interconnected legacy infrastructure that is difficult to patch → systemic risk.
  5. Increased dependence on foreign AI for vulnerability detection, response and patching in the post-Mythos era.

Reasoning behind "supply chain security" in this context

Security of the whole depends on the weakest shared component. Using geopolitics vocabulary (supply-chain resilience, de-risking) makes the answer match the examiner's expected "primary argument of the day" — the lecturer calls these keywords of the topic.

7.2 BFSI — Banking, Financial Services & Insurance 1:00 – 1:03, 2:20 – 2:35

  • Includes banking, financial services, insurance, fintech (CRED, Groww etc.), payment gateways / aggregators (also used to pay fees).
  • Threat: promotes digital robbery — mass looting of bank accounts (per IDSA analysis); could paralyse payment gateways and international payment systems.
  • Why BFSI is more prone — box:
    1. Uses shared digital infrastructure — cloud services, payment networks, interconnected databases (HDFC/ICICI/Axis net banking built on outsourced or shared software; co-operative and small banks hire software from third parties).
    2. Structural issue (inherent, hard to solve):
      • Complexity — Core Banking Solution (CBS) underpins inter-bank transfers (NEFT/RTGS); centralised technology structure, slow to process and difficult to change.
      • Legacy-system vulnerabilities — Indian banks built specialised software stuck around CBS; legacy systems carry zero-day vulnerabilities that may have evaded cyber audits and are exposed to Mythos.
  • Cyber audits are mandatory for big companies/critical sectors under CERT-In mechanisms — yet loopholes remain. If CBS is flawed, all banks' stacks built on it are exposed.

7.3 Digital Public Infrastructure (DPI) 1:03 – 1:07, 2:35 – 2:40

  • Examples: Aadhaar (JAM trinity is based on Aadhaar), CoWIN, DigiYatra, DigiLocker, PFMS (Public Fund Management System), Sanchar Saathi, Chakshu (the "eyes" of government to detect cyber fraud — note: the detection platform itself has 100% vulnerability if the underlying code has an unpatched flaw).
  • India's software stack is interconnected and based on cloud-based infrastructure, open-source software, shared libraries. Examples: CoWIN and DigiYatra.
  • Significant concern given increasing digitalisation in the economy, increasing digital literacy and increasing use of UPI-based financial architecture.

Mythos, a frontier AI model developed by Anthropic with unusually strong capability in detecting software vulnerabilities, cyber-security reasoning and software analysis, marks a shift from human-led to machine-led cyber security. By finding zero-day vulnerabilities at machine speed and scale, it is a double-edged sword for India's cyber-security architecture.

Prelims trap MCQs

Q1
A "zero-day vulnerability" refers to:
A. A flaw that can be fixed within a day of discovery
B. An undisclosed flaw in software or hardware, unknown to the developer, that threat actors can exploit
C. A bug that appears on the first day of a software release
D. A flaw that appears only in government software
Answer: B. "Zero" = zero days available to fix, not release date.
Q2
Consider the statements: (1) A "patch" is a fix issued for a software bug. (2) Mythos is a frontier AI model developed by OpenAI. Which is correct?
A. 1 only
B. 2 only
C. Both
D. Neither
Answer: A. Mythos is by Anthropic.
Q3
Under which law is CERT-In the nodal agency for cyber-security incidents?
A. Section 43 IT Act
B. Section 70B IT Act
C. Section 66F IT Act
D. DPDP Act 2023
Answer: B. 70A = NCIIPC (critical information infrastructure); 66F = cyber terrorism.
Q4
Which of these is used for supervisory control of industrial systems such as wind turbines?
A. SWIFT
B. SCADA
C. CBS
D. UPI
Answer: B. Supervisory Control and Data Acquisition.

Glossary

Frontier AI model
Latest, most advanced AI systems: complex reasoning, autonomous task execution, code generation, cyber-security capability.
Zero-day vulnerability
Undisclosed flaw in software/hardware unknown to its developer; zero days to fix.
Patch
Fix for a software bug/vulnerability.
Threat actor
Entity (state or non-state) that can exploit a vulnerability.
Defender overload
AI finds flaws faster than defenders can verify, prioritise and patch.
Supply-chain security
Risk through shared libraries, open-source parts, cloud services and third-party vendors.
Legacy system / software
Old software (10–20+ years) still running core operations; hard to patch.
Critical infrastructure
Power, ports, airports, hospitals, telecom, highways etc.
BFSI
Banking, Financial Services and Insurance.
DPI
Digital Public Infrastructure: Aadhaar, CoWIN, DigiYatra, DigiLocker, UPI.
CBS
Core Banking Solution — central software behind inter-bank transfers.
SCADA
Supervisory Control and Data Acquisition — controls industrial/energy systems.
MeghRaj
Government of India cloud initiative.
Project Glasswing
Anthropic's limited-access cohort (~40 organisations) to use Mythos for defence.
Hybrid / grey-zone warfare
Conflict below the threshold of open war using cyber, information and proxy means.
AI cyber arms race
Competition among firms/states to build frontier models that can exploit/defend zero-days.
